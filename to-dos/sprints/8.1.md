# S-AUTH-8.1: FIDO2 CTAP2.1 hardware key core and HMAC-secret derivation

Status: Planned; task IDs are allocated in [ROADMAP.md](../../ROADMAP.md).

## Goal and Scope

Implement the core FIDO2 / WebAuthn CTAP 2.1 hardware backend in `src/authy_local/backends/fido2.py` utilizing `python-fido2` and the `hmac-secret` / WebAuthn PRF extensions to dynamically derive cryptographic keys from physical hardware security tokens (YubiKey 5 Series, SoloKey, Nitrokey) upon physical touch presence and user PIN verification.

Non-goals: Modifying software TOTP algorithms or existing GPG/TPM stores.

## Entry Conditions and Dependencies

Dependencies: Phase 0–7 completed; `python-fido2` dependency available.

## Tasks

- [ ] **T-AUTH-088:** Implement physical authenticator discovery, USB/NFC device enumeration, and CTAP 2.1 capability negotiation in `src/authy_local/backends/fido2.py`.
- [ ] **T-AUTH-089:** Implement credential generation with `hmacCreateSecret` and assertion evaluation with `HMACGetSecretInput` applying standardized salt parameters.
- [ ] **T-AUTH-090:** Implement dynamic TOTP seed decryption and key derivation using the hardware-returned HMAC-SHA-256 output.
- [ ] **T-AUTH-091:** Build comprehensive synthetic CTAP2 device mock suite in `tests/test_fido2_backend.py` covering device enumeration, pin verification, touch timeouts, and crypto derivation.

## Outputs

- Core hardware backend `src/authy_local/backends/fido2.py`.
- Automated test suite `tests/test_fido2_backend.py`.

## Validation and TDD

- Synthetic CTAP2 mock authenticators validating WebAuthn PRF and `hmac-secret` key derivation paths.
- Assertion that no plaintext seed persists on disk without physical authenticator authorization.
