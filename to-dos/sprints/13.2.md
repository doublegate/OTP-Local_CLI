# S-AUTH-13.2: Platform biometric authorization (Touch ID, Windows Hello, fprintd)

Status: Planned; task IDs are allocated in [ROADMAP.md](../../ROADMAP.md).

## Goal and Scope

Implement hardware-backed biometric verification across supported operating systems (macOS Touch ID, Windows Hello, Linux `fprintd` / PAM) to protect token generation and secret decryption operations behind local user presence challenges.

Non-goals: Unattended remote biometric bypasses or custom biometric template storage.

## Entry Conditions and Dependencies

Dependencies: S-AUTH-13.1 completed; platform biometric framework availability.

## Tasks

- [ ] **T-AUTH-134:** Implement macOS Touch ID authorization using `LocalAuthentication.LAContext` with localized reason prompts.
- [ ] **T-AUTH-135:** Implement Windows Hello biometric challenge using `Windows.Security.Credentials.UI.UserConsentVerifier`.
- [ ] **T-AUTH-136:** Implement Linux biometric integration via D-Bus `net.reactivated.Fprint.Device` and PAM conversation fallback.
- [ ] **T-AUTH-137:** Add CLI flag `--biometric` and configuration policy toggle `require_biometric` with test suite in `tests/test_biometrics.py`.

## Outputs

- Biometric verification module `src/authy_local/biometrics.py`.
- Automated test suite `tests/test_biometrics.py`.

## Validation and TDD

- Mocked platform sensor tests verifying prompt rendering, success callbacks, and timeout cancellations.
- Fail-closed security validation ensuring secrets remain encrypted when verification is refused.
