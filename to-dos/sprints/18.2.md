# S-AUTH-18.2: Cloud provider secrets engines (AWS, GCP, Azure Key Vault)

Status: Planned; task IDs are allocated in [ROADMAP.md](../../ROADMAP.md).

## Goal and Scope

Implement cloud secrets providers in `src/authy_local/backends/cloud_vaults.py` supporting AWS Secrets Manager, Google Cloud Secret Manager, and Azure Key Vault with zero-credential metadata identity.

Non-goals: Hardcoding cloud secrets or cloud SDK bloat; uses lightweight async REST clients.

## Entry Conditions and Dependencies

Dependencies: S-AUTH-18.1 completed; cloud IAM metadata endpoint discovery.

## Tasks

- [ ] **T-AUTH-184:** Implement AWS Secrets Manager adapter with AWS SigV4 request signing and IMDSv2 metadata auth.
- [ ] **T-AUTH-185:** Implement Google Cloud Secret Manager adapter with service account and ADC token exchange.
- [ ] **T-AUTH-186:** Implement Azure Key Vault adapter with Azure Managed Identity and OAuth2 client credentials.
- [ ] **T-AUTH-187:** Build automated mock cloud endpoint and credential rotation test suite in `tests/test_cloud_vaults.py`.

## Outputs

- Cloud vault module `src/authy_local/backends/cloud_vaults.py`.
- Automated test suite `tests/test_cloud_vaults.py`.

## Validation and TDD

- Mock AWS, GCP, and Azure metadata endpoints verifying role assumption and secret retrieval.
- Memory zeroization tests confirming all decrypted secret bytes are scrubbed after token generation.
